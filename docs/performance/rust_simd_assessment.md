# rust_lib SIMD 研究

日期：2026-10-10。范围：研究候选热点，不修改运行时算法、不替换已安装扩展。

## 结论

先建立 release 基线，再优化台阶检测的扫描次数。显式 SIMD 的首个候选是 VMD 的频谱迭代，而不是 FFT 或波形 LOD。EMD 筛分循环的独立实验没有显示稳定收益。

| 优先级 | 位置 | 建议与依据 |
| --- | --- | --- |
| 前置项 | 当前 Python 环境的 rust_lib | 安装的扩展 SHA-256 与 target/debug/librust_lib.so 一致。先用 release 建立基线；升级 rustc 不会自动重编译已安装的扩展。 |
| 高：先改算法 | step.rs / detect_step_core | K 次完整 argmax 为 O(KN)。单遍维护 top-K 原型比保留原算法加 AVX 获益明显更多；保持同值时优先较早索引。 |
| 高：SIMD 候选，未验证收益 | vmd.rs / vmd_core 的频谱更新、能量归约 | 每个模态、每次迭代遍历频点；包含大量复数加减、实数除法和平方。可在一个模态内部并行处理频点。模态之间有更新依赖，不可直接同时更新。先确认 release 热点占比，再比较 AoS/SoA 内存布局和向量宽度。 |
| 中：先测热点分布 | diurnal.rs / detrended、harmonic_signal、RMS、加权拼接 | 外围运算可以 SIMD，但可能由每窗两次 SVD 主导。默认趋势/谐波列数较少，沿短列向量化收益有限。优先考察跨样本布局、工作缓冲复用、相同有效行模式下分解复用。 |
| 中低 | decimate.rs / nan_boxcar_decimate_core | 窗口较大时可以向量化有限值掩码与求和；小 factor 时调度/归约开销明显。现有 Rayon 已经并行。求和重排会改变低位结果。 |
| 低，已有反例 | emd.rs / sift 更新和范数 | 可写 SIMD，但 100 万点独立实验标量和 AVX 都约 1.2 ms，没有稳定优势；读写数组成本较高。完整 EMD 还含极值查找、样条递推和分配，不能把该循环加速等同于全算法加速。 |
| 低 | decimate.rs / decimate_core、build_lod_pyramid_core | LOD 桶通常只有约 5 点，额外要求返回极值原始位置、忽略 NaN、保留同值最早位置。Rayon 已处理桶并行；修复连续数组入口后没有证据表明手写 SIMD 是首要瓶颈。大桶独立 minmax 可另行测量。 |
| 不宜首选 | step.rs / 前缀和；emd.rs / 样条求解、平台极值 | 前缀和、三对角递推具有顺序依赖，平台极值检测还有可变长度遍历。应先考虑算法/分块方案，普通逐元素 SIMD 不直接适用。 |
| 保留现有库 | VMD 的 FFT | 项目使用 rustfft 6.4.1、默认 features 和 FftPlanner；支持时自动选择 AVX/SSE/NEON。无需重新手写 FFT 的 SIMD。 |
| 不宜首选 | MAT/TXT/XLSX 读取 | 存在解压、字符串解析、I/O、格式处理。未经热点采样不应按数值循环处理。 |

## 可复现的优化编译实验

独立源文件：`simd_research_probe.rs`。机器为 AMD Ryzen 7 8845H，使用 rustc 1.99.0，`-C opt-level=3`；没有全局启用 target-cpu=native。AVX 原型在运行时检测 CPU 后调用。临时原型包含少量 CPU 分派入口 unsafe，计算内核使用安全数组访问及支持的 SIMD 运算。

```bash
rustc --edition=2024 -C opt-level=3 docs/performance/simd_research_probe.rs -o /tmp/mtpro-simd-probe
/tmp/mtpro-simd-probe
```

台阶检测：100 万点，K=20，阈值 0，确定性的有限随机样数据，含 NaN 和相同最大值；预热一次、7 次计时取中位数。

| 优化编译下的独立实现 | 一次代表性运行 |
| --- | ---: |
| 仓库原始重复 argmax 函数 | 14.023 ms |
| AVX 保留 K 次扫描，向量最大值后寻找最早匹配索引 | 8.585 ms |
| 单遍维护大小为 K 的堆 | 1.035 ms |

三个实现对该输入返回相同索引。数字只说明该机器、该数据形态下的取舍；top-K 的最坏更新成本及不同 K、峰值分布需另测。原型不是完整边界验证后的替代实现。

EMD：100 万点，一次筛分更新及两个范数，预热一次、11 次取中位数。代表性运行：标量 1.182 ms、AVX 1.186 ms。另一次运行为 1.604/1.497 ms，差异不足以证明稳定加速。更新数组逐点相等，范数最大相对差约 2.33e-15。完整分解的收敛次数和输出模态仍需专门验证。

编译器探针：按 EMD 筛分公式提取的循环在优化后的 LLVM IR 中没有向量归约；显式 SIMD 仍未带来明显收益。提取的日变加权拼接循环加上等长切片断言后，`target-cpu=native` 优化编译能够生成向量乘加。此结果仅说明编译器有自动向量化能力，不证明当前扩展或其完整函数已使用同样的指令。

## 当前安装扩展的探索性计时

这些数字来自当前安装的 **debug 扩展**，不作为 release 下 SIMD 提速倍数的依据。各任务参数不同，不能直接据此比较算法优劣。合成输入、预热一次、3 次取中位数。

| 任务 | 输入及设置 | 耗时 |
| --- | --- | ---: |
| 台阶峰值搜索 | 100 万点，K=20，绝对差分正弦信号 | 276.830 ms |
| 波形 LOD | 100 万点 | 21.108 ms |
| minmax | 100 万点，1000 桶 | 2.750 ms |
| NaN-aware boxcar | 100 万点，factor=5/20/1000 | 2.764 / 1.412 / 0.827 ms |
| VMD | 32768 点，4 模态，上限 100 次迭代 | 1687.560 ms |
| EMD | 32768 点，上限 4 IMF、20 次筛分，容差 0.05 | 44.743 ms |

没有测得 VMD 或日变拟合的 SIMD 提速倍数。上述排序结合源码依赖结构与探索计时，仍需要 release 下函数内部热点采样。

## 后续试验要求

1. 用同一源码、数据、线程数和 release 优化分别测试，单独记录 Python/NumPy 交接和数据整理时间。
2. 优先研究台阶 top-K；再为 VMD 保留标量参考实现，比较向量内核的端到端收益。
3. 验证 NaN、无穷值、全缺失、同值取最早索引、尾部不足向量宽度和输入长度边界。
4. VMD/EMD 的归约重排会影响收敛判断。比较重构误差、频率、模态和迭代次数；不要只检查一次运算的近似相等。
5. 发布构建使用 CPU 运行时分派和通用回退，不将本机 AVX/AVX-512 指令集要求施加到所有用户机器。
